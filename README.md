# Zigbee Датчик Потока Воды и Температуры (2× YF-B5 + DS18B20)

Zigbee-устройство на базе ESP32-C6 для банного чана: расход воды двумя
датчиками YF-B5 (подача/обратка) и температура одним или несколькими
DS18B20 на общей 1-Wire шине. Питается от USB-C (постоянно), в сети
выступает как **Router** — укрепляет mesh для других (в т.ч. battery-powered)
устройств.

Все сенсоры объединены в одной прошивке намеренно — физически стоят в одной
точке монтажа, разводить два отдельных ESP32-C6 под одно место смысла нет.

## Возможности

- Расход воды **л/мин** на каждом из двух YF-B5 (подача/обратка)
- Температура **°C** с каждого подключённого DS18B20 (1-3 датчика в этой
  установке, прошивка поддерживает до 10 без пересопряжения с ZHA)
- Передача данных по **Zigbee** (кластеры Flow Measurement и Temperature
  Measurement)
- Интеграция с **Home Assistant** (ZHA)
- Без встроенной логики поверх телеметрии (детект протечки, пороги и т.п.) —
  это задача HA-автоматизаций, прошивка только отдаёт сырые показания

## Железо

| Компонент | Модель | Примечания |
| --------- | ------ | ---------- |
| Контроллер | ESP32-C6 SuperMini | Постоянное питание через USB-C |
| Сенсор 1 | YF-B5 (подача) | Pulse output (открытый коллектор) |
| Сенсор 2 | YF-B5 (обратка) | Pulse output (открытый коллектор) |
| Сенсор(ы) температуры | 1-3× DS18B20 | Общая 1-Wire шина, свой ROM-адрес у каждого |

## Подключение

### YF-B5 (расход)

```text
YF-B5 (подача):  Red → 5V(VBUS)   Black → GND   Yellow → GPIO18
YF-B5 (обратка): Red → 5V(VBUS)   Black → GND   Yellow → GPIO19
```

Оба YF-B5 питаются от 5V-пина (VBUS) SuperMini — датчик штатно работает от
4.5–18V DC, отдельный блок питания не нужен, пока контроллер подключён по
USB-C. Оба датчика можно смело запитать от одного и того же 5V-пина — ток
потребления единицы-десятки мА, USB тянет это без проблем.

Сигнальный провод (Yellow) — внешний pull-up **не обязателен**: драйвер PCNT
сам включает внутренний pull-up на этом GPIO при создании канала (проверено
на стенде — без внешнего резистора счёт импульсов работает штатно). Если
будете делать длинную проводку до датчиков (не на макетке, а финальная
сборка) — можно добавить внешний резистор **4.7–47кОм к 3.3V** на каждую
сигнальную линию для надёжности на наводках, но для стенда и коротких
проводов это не нужно.

> **Важно:** резистор должен быть именно в диапазоне кОм, не Ом. Резистор на
> 10 **Ом** вместо 10 **кОм** на практике полностью забивает линию в HIGH —
> ни датчик, ни ручное замыкание на GND её не продавят (на 3-м цветовом
> кольце резистора разница между ними — чёрное vs оранжевое).
>
> **GPIO18/19 выбраны намеренно** (`main/config.h`): обычные GPIO, свободные
> от известных ограничений SuperMini — не strapping-пины (0/4/5/8/9), не
> антенный switch (3/14, см. `configure_internal_antenna()` в
> `main/main.c`), не USB D+/D- (12/13, по ним работает консоль). Если на
> вашем экземпляре SuperMini разводка отличается — GPIO в `config.h`
> меняются одной строкой.

### DS18B20 (температура)

```text
DS18B20 ×N:  GND → GND   VCC → 3V3   DATA → GPIO20
```

Все датчики DS18B20 подключаются к одним и тем же трём линиям (GND/VCC/DATA)
— это штатный режим 1-Wire, каждый сенсор идентифицируется своим уникальным
64-битным ROM-адресом. На линию DATA нужен pull-up **4.7кОм к 3.3V** (если
используете терминальную плату с уже встроенным резистором — отдельный не
нужен).

## Калибровка расхода

Коэффициент `FLOW_*_PULSES_PER_LITER` в `main/config.h` по умолчанию — 450
импульсов/литр (типовая формула для этого семейства датчиков,
`F(Hz) = 7.5 × Q(л/мин)`). **Это нужно проверить по датащиту вашего
конкретного экземпляра YF-B5 или откалибровать по измеренному объёму** —
разные партии/варианты диаметра дают разный K-фактор. Значение правится в
прошивке без изменения структуры кластеров (пересопряжение с ZHA не
требуется).

Разрешение кластера Flow Measurement — ~1.67 л/мин на шаг (ZCL-спека задаёт
`MeasuredValue = 10 × расход(м³/ч)`), этого достаточно для контроля
"течёт/не течёт" и грубой скорости потока, но не для точного учёта объёма.

## Прошивка

Прошить можно прямо в браузере (Chrome / Edge):

**[Открыть веб-прошивалку](https://djubb.github.io/zigbee-waterflow/)**

1. Подключите ESP32-C6 по USB
2. Нажмите кнопку «Install»
3. Выберите COM-порт устройства
4. Дождитесь окончания прошивки

Если устройство не определяется — зажмите кнопку **BOOT** перед подключением USB.

## Сборка из исходников

Требуется [ESP-IDF v5.3+](https://docs.espressif.com/projects/esp-idf/en/stable/esp32/get-started/index.html).

```bash
git clone https://github.com/djubb/zigbee-waterflow.git
cd zigbee-waterflow
idf.py set-target esp32c6
idf.py build
idf.py flash
```

## Подключение к Home Assistant

1. Перейдите в **Настройки → Устройства и службы → ZHA**
2. Нажмите **Добавить устройство**
3. Включите питание контроллера по USB-C — при первом старте он автоматически
   попробует присоединиться к сети (network steering)
4. После подключения появятся:
   - 2 сущности расхода воды (эндпоинты 10 и 11) — подача и обратка
   - сущности температуры (эндпоинты 20+) — по одной на каждый физически
     подключённый DS18B20. Привязка «эндпоинт → физический датчик» идёт по
     возрастанию ROM-адреса и пересчитывается **при каждой загрузке** —
     стабильна только пока набор подключённых датчиков не меняется.
     Остальные эндпоинты из запаса (до 10 штук) остаются неактивными, пока
     не подключите датчик на освободившийся слот — список Zigbee-кластеров
     при этом не меняется, повторное сопряжение не требуется.

## Сброс к заводским настройкам

- Удалите устройство из ZHA-интерфейса — девайс перейдёт в режим ожидания сопряжения
- Либо сотрите flash: `idf.py erase-flash`, затем прошейте заново

> При смене конфигурации Zigbee-кластеров необходимо стирать flash во избежание
> boot loop из-за несовместимости NVS-хранилища.

- [main/flow_task.c](main/flow_task.c) — счёт импульсов (PCNT) и расчёт л/мин для YF-B5
- [main/ds18b20_task.c](main/ds18b20_task.c) — сканирование 1-Wire шины и опрос DS18B20
- [main/zigbee.c](main/zigbee.c) / [main/zigbee.h](main/zigbee.h) — Zigbee-утилиты
- [main/zigbee_task.c](main/zigbee_task.c) — Zigbee-инициализация, эндпоинты, кластеры Flow Measurement и Temperature Measurement
